# Лимиты бесплатных тарифов и проверка доступа

Проверено по официальным страницам 13 октября 2026 года. Это включённые квоты тарифов, а не измерение текущего использования вашего проекта.

## GitHub Pages

Источник: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits

- Публичный репозиторий на GitHub Free: публикация бесплатна.
- Опубликованный сайт: не более 1 ГБ.
- Трафик: мягкий лимит 100 ГБ/месяц.
- Сборки: мягкий лимит 10/час. Он не относится к пользовательским GitHub Actions workflow.
- Время сборки: до 10 минут. Сайт статический, серверная часть здесь не запускается.
- GitHub запрещает использовать Pages для коммерческого SaaS/электронной коммерции и рекомендует не использовать сайты Pages для чувствительных операций, например отправки паролей. Pages был выбран для прототипа. Для полноценного продукта с аккаунтами следует выбрать подходящий хостинг; собственный платный домен для этого не обязателен.

## Supabase Free

Источник: https://supabase.com/pricing

- 2 активных бесплатных проекта.
- База PostgreSQL: 500 МБ на проект.
- Auth: 50 000 активных пользователей в месяц (MAU), не лимит общего количества зарегистрированных пользователей.
- Исходящий трафик: 5 ГБ/месяц. Дополнительно 5 ГБ кэшированного трафика Storage/CDN; это не дополнительные 5 ГБ для чтения базы.
- Хранение файлов: 1 ГБ, максимальная загрузка файла — 50 МБ. Текущий дашборд хранит текст в базе, а не в файловом Storage.
- API-запросы: без количественной месячной квоты, но трафик и ресурсы базы ограничены.
- Проект приостанавливается после недели без активности.
- Автоматические резервные копии в бесплатный тариф не включены; сохраняйте экспорт задач отдельно.
- Realtime: 200 одновременных подключений, 2 млн сообщений/месяц. Сейчас приложение использует REST и периодическую проверку версии, а не Realtime.
- Edge Functions: 500 000 вызовов/месяц. Сейчас не используются.

Почта: https://supabase.com/docs/guides/auth/auth-smtp

Встроенный SMTP предназначен для тестирования: письма только на адреса членов организации Supabase, сейчас до 2 сообщений/час, без гарантии доставки. Для приглашений и сброса пароля коллегам нужен собственный SMTP. Ручное создание подтверждённых пользователей не зависит от доставки письма.

## Проверено на реальном проекте

- Публичная регистрация отключена (`disable_signup: true`).
- Анонимные GET/POST/PATCH/DELETE таблицы dashboards заблокированы: HTTP 401, PostgreSQL 42501.
- Для записи/удаления использован только синтетический UUID, реальные пользовательские данные не запрашивались и не изменялись.
- 13 октября 2026 года пользователь запустил опубликованную проверку с двумя пустыми тестовыми аккаунтами на реальном Supabase и сообщил результат: «Все 9 проверок пройдены». Это подтверждение по отчёту пользователя; агент не получал его пароли/токены и не запускал авторизованную проверку самостоятельно.
- По этому результату прошли чтение/запись своего дашборда, запрет чтения чужого в обе стороны, ограничение списка своими строками, запрет чужой правки/вставки, анонимный доступ, конфликт версии и очистка проверочных записей.
- Результат относится к текущим правилам доступа и сценариям теста. Это целевая проверка изоляции, а не полный аудит безопасности. Повторяйте её после изменений RLS/авторизации. Тесты на имитированном API сами по себе не доказывают состояние реального RLS.

## Автоматическая проверка двух аккаунтов

На сайте: «Мой аккаунт» → «Проверить разграничение доступа».

Введите email/пароли двух разных пустых тестовых аккаунтов, созданных в вашем Supabase, и запустите проверку. Пароли не отправляйте в чат. Они используются напрямую для входа в Supabase и не сохраняются приложением. Тестовые токены хранятся в памяти; текущая сессия приложения не заменяется. Тестовые сессии закрываются с `scope=local`.

Проверяются 9 условий: чтение/запись своего дашборда каждым аккаунтом, чтение чужих задач в обе стороны, ограничение списка своими строками, запрет чужой правки, запрет вставки от чужого имени, анонимный доступ и конфликт версии.

Аккаунты с непустыми задачами отвергаются до записи. После теста возвращается исходный пустой payload; если строки раньше не было, останется пустой дашборд. При появлении посторонних изменений во время теста данные не перезаписываются и отчёт сообщает о невозможности очистки. Не закрывайте страницу до конца. TXT-отчёт не содержит пароли, токены или email.

## Проверки кода

- `node tests/security-check.cjs` — безопасная очистка, остановка на непустых аккаунтах, обнаружение нарушения изоляции, конкурентные изменения, ошибки очистки, отсутствие секретов в отчёте. API имитирован.
- `node tests/security-ui.cjs` — браузерная проверка интерфейса и отчёта на имитированном API.
- `node tests/cloud-poll.cjs` — проверка версии перед полной загрузкой задач и повторная проверка личности после обновления токена.

Фоновая проверка каждые 30 секунд теперь сначала получает только revision. Полный JSON загружается при изменении. Это уменьшает расход трафика и сохраняет текущий фильтр при отсутствии обновлений.
