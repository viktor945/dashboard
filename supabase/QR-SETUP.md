# Включить вход на телефоне по QR-коду

Сайт уже содержит окно QR-входа. Для входа без пароля один раз нужно добавить серверную часть в ваш проект Supabase. Публичного ключа сайта для этого недостаточно. Секретные ключи в GitHub, настройках сайта или чате указывать не нужно.

## 1. Создать служебную таблицу

1. Откройте [SQL Editor вашего проекта](https://supabase.com/dashboard/project/uyerbmdknxdaposzoiei/sql/new).
2. Откройте [готовый SQL-файл](https://raw.githubusercontent.com/viktor945/dashboard/main/supabase/device-link.sql), скопируйте весь текст в SQL Editor.
3. Нажмите **Run**. Скрипт можно запускать повторно. Он не меняет существующие задачи и таблицы авторизации.

## 2. Опубликовать серверную функцию

1. В том же проекте откройте **Edge Functions** → **Deploy a new function** → **Via Editor** (названия могут немного отличаться).
2. Назовите функцию строго **device-link**.
3. В файле `index.ts` замените пример целиком [готовым кодом функции](https://raw.githubusercontent.com/viktor945/dashboard/main/supabase/functions/device-link/index.ts).
4. Нажмите **Deploy function**.
5. В настройках этой функции отключите **Verify JWT with legacy secret / Enforce JWT verification**. Это нужно телефону, у которого ещё нет сессии. Функция сама проверяет аккаунт компьютера через Supabase Auth; подключение телефона дополнительно требует секретного QR, совпадения кодов и подтверждения компьютером.

Переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляются функции самим Supabase. Их не нужно добавлять в код или пересылать. Для текущего адреса `https://viktor945.github.io/dashboard/` дополнительные настройки не требуются. Если сайт переедет, задайте **только серверной функции** переменную `DASHBOARD_URL` с новым полным HTTPS-адресом.

Если вы используете Supabase CLI вместо редактора:

```sh
supabase functions deploy device-link --project-ref uyerbmdknxdaposzoiei --no-verify-jwt
```

SQL из первого шага всё равно нужно выполнить. Команда требует вашего входа в CLI; сайт и агент не получают административные ключи.

## 3. Проверить на двух пустых тестовых аккаунтах

1. Войдите на компьютере в тестовый аккаунт A. Откройте **Мой аккаунт → Создать QR-код для входа**.
2. Отсканируйте код своим телефоном. Нажмите на телефоне **Подключить этот телефон**.
3. Сверьте шестизначные коды. Только если они совпадают, нажмите на компьютере **Код совпадает — подключить телефон**.
4. Телефон должен открыть данные A без ввода пароля. Если выбрано «Запомнить вход», закройте вкладку и откройте сайт снова: аккаунт должен сохраниться.
5. Повторный вход с тем же QR на другом телефоне должен отклоняться. Новый QR, отмена и истечение пяти минут должны блокировать старое подключение.
6. Выход на компьютере завершает только его сессию. Проверьте, что телефон продолжает работать; выход на телефоне удаляет его сохранённый вход.
7. Повторите с тестовым аккаунтом B: он должен получить только свои данные. Не отправляйте кому-либо QR, пароли и сессионные токены.

После успешной проверки используйте свой обычный аккаунт.

## Что защищает доступ

- QR содержит случайный одноразовый секрет с 256 битами энтропии. Это не пароль и не текущий access/refresh token компьютера. Он очищается из адресной строки телефона до входа.
- Служебная таблица недоступна `anon` и `authenticated`; SQL-функции разрешены только `service_role`. Значения секретов QR и телефона хранятся как SHA-256.
- Первый телефон привязывается к запросу отдельным случайным доказательством. Компьютер подтверждает вход только после сравнения кода. Сервер проверяет владельца через Auth, а не берёт user_id из браузера.
- Только после подтверждения Auth создаёт magic-link token для подтверждённого email владельца. Сервер отдаёт его один раз одному телефону; телефон обменивает его на новую независимую сессию. QR, отменённый или просроченный до выдачи токена, больше не работает. После выдачи токен дополнительно защищён одноразовой проверкой Supabase Auth.
- Генерация magic-link выполняется сервером и не отправляет письмо. Текущая сессия компьютера не копируется. Включено ограничение пяти новых QR в минуту на аккаунт; новый QR отменяет предыдущий.
- Аккаунты с подтверждённым вторым фактором (MFA) подключаются обычным способом: QR-вход не обходит второй фактор.
- Сохранение входа на своём устройстве использует browser localStorage, как обычные веб-приложения. Без галочки вход хранится до закрытия вкладки. Резервные копии задач и отчёты не содержат сессий.
- Просроченные строки удаляются при следующей генерации QR после суток; отмена и использование немедленно удаляют одноразовый токен из строки. Без новых генераций просроченные строки могут оставаться в таблице, но использовать их нельзя.

## Проверки разработки

Проверки используют синтетические данные; Supabase Auth в них имитируется. Это **не заменяет проверку живого проекта после публикации**.

```sh
npm --cache /tmp/poryadok-npm-cache install --prefix /tmp/poryadok-qr-test --no-save @electric-sql/pglite@0.5.13 jsqr@1.4.0 pngjs@7.0.0
node tests/device-link-server.mjs
PORYADOK_TEST_URL=http://127.0.0.1:8016/ node tests/device-link-browser.cjs
```

Серверные проверки запускают настоящие SQL-функции и права PostgreSQL через PGlite. Браузерная проверка независимо декодирует изображение QR, использует два изолированных браузера и проверяет отдельные сессии, подтверждение, повторное использование, сохранённый вход и выход только с текущего устройства. Для неё также нужны Playwright и Chromium, как у остальных тестов проекта.
