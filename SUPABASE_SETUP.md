# Подключение личных аккаунтов

Облачный режим подготовлен, но не активен, пока `config.js` не содержит параметры проекта. Тесты с тестовым API не подтверждают работу настоящего Supabase или его правил доступа.

1. Создайте проект на https://supabase.com/. Пароль базы храните у себя.
2. В SQL Editor выполните целиком [supabase/schema.sql](supabase/schema.sql). Скрипт создаёт таблицу личных дашбордов с RLS и проверкой владельца при чтении/записи. Повторное выполнение сохраняет данные.
3. В Authentication → URL Configuration установите Site URL `https://viktor945.github.io/dashboard/` и добавьте этот же адрес в Redirect URLs. Без этого приглашения и сброс пароля могут перенаправлять на другой адрес.
4. В Authentication → Providers → Email отключите публичную регистрацию (Allow new users to sign up). Вход будет только для пользователей, которых владелец пригласил через Authentication → Users → Invite user. Включите email/password. Для рассылки коллегам настройте собственный SMTP: встроенная тестовая доставка Supabase имеет ограничения по адресатам и частоте.
5. Возьмите Project URL и Publishable key через Connect / API Keys. Эти параметры публичные. Заполните `config.js`, отправьте изменение в GitHub. Ни пароль базы, ни secret/service_role, ни ключ ИИ в браузерный код не помещаются.
6. Пригласите свой email. Откройте ссылку приглашения, задайте пароль (минимум 12 символов в интерфейсе). После входа загрузится личный дашборд.
7. В «Мой аккаунт» нажмите «Добавить задачи с этого устройства» для переноса локальных задач. Облачные данные и локальная копия сохраняются. Дубли определяются по ID.

## Проверка перед приглашением отдела

Нужны два отдельных тестовых аккаунта и браузерные профили:
- У пользователя A создайте задачу и отчёт. У B они не должны появиться.
- С токеном B запросите строку A через REST: ответ должен быть пустым. Попытка вставки/обновления строки A не должна изменять её. Без токена таблица недоступна.
- Войдите аккаунтом A во втором браузере, проверьте перенос изменений. В первом браузере дашборд обновляется каждые 30 секунд, когда формы закрыты, или кнопкой «Обновить из облака».
- Проверьте конкурентную правку: устаревший браузер не должен перезаписать новую версию; он получает сообщение об обновлении данных.
- Проверьте приглашение, сброс пароля и выход. После выхода должны быть видны только локальные задачи устройства, а не данные аккаунта.
- Проверьте потерю сети: интерфейс сообщает, что запись не сохранена; не показывает ложного успеха.

## Текущие ограничения

Каждый аккаунт хранит свой дашборд отдельной строкой JSON. Это подходит для небольшого личного пилота, но общие задачи и чат отдела потребуют другой модели данных и ролей. Облачное редактирование требует сети. Сессия хранится в sessionStorage текущей вкладки; закрытие вкладки потребует входа заново. Заметки — личный журнал, не чат коллег и не диалог с ИИ. Авторизация и доступ проверяются Supabase; публичный сайт не содержит привилегированных ключей.

Повторяющиеся задачи, шаблоны/чек-листы, правила распределения и ИИ-помощник остаются следующими этапами. ИИ требует отдельного серверного обработчика и ключа провайдера, и не должен автоматически получать рабочие записи.
