# Порядок

Личный дашборд задач: локальный режим по умолчанию и подключаемый облачный режим Supabase. Интеграции с Битрикс24 пока нет.

## Запуск

Из `/workspace/dashboard`:

```sh
python3 -m http.server 8001 --bind 0.0.0.0
```

Откройте путь `/` через свой способ доступа к серверу. В облачном onboarding предпросмотр не поддерживается. Для локальной работы скачайте проект и запустите ту же команду из корня репозитория.

Зависимости и сборка не требуются: HTML, CSS, JavaScript, Python 3 для статического сервера. Используйте современный браузер и HTTP, а не открытие HTML как файла.

## Возможности

- Быстрый ввод задач, создание своих категорий, группировка и список.
- Приоритет, срок, статус, источник задачи и необязательная ссылка на Битрикс24.
- Мой день, входящие, завершённые, поиск по названию, описанию и заметкам.
- Заметки и события внутри карточки. Изменение статуса записывается в историю.
- Меню «Импорт / экспорт»: читаемый CSV для Excel (UTF-8 с BOM, разделитель точка с запятой, экранирование формул) и резервная копия JSON.
- CSV включает все задачи, заметки и полную хронологию. Это отчёт, обратный импорт CSV пока не поддерживается.
- Восстановление JSON заменяет текущие данные после подтверждения. Файлы Битрикс24 пока не поддерживаются.
- Демопримеры добавляются только по кнопке на пустом экране.

Данные сохраняются в localStorage текущего браузера для конкретного адреса сайта. Между устройствами и браузерами они не синхронизируются. Регулярно делайте экспорт: очистка данных браузера удалит задачи. Одновременное редактирование в нескольких вкладках не поддерживается. Не используйте приложение как единственное хранилище критичных рабочих данных. Нет напоминаний, чата с коллегами или автоматической синхронизации с CRM. Аккаунты и синхронизация устройств требуют подключения Supabase.

## Личный журнал и список задач

В карточке задачи можно отправлять заметки, отчёты и уточнения с датой. Это личный журнал, не общий чат. Кнопка «Добавить список» создаёт по одной задаче на строку (до 500); показывает предпросмотр и пропускает совпадения по названию, не удаляя существующие задачи.

## Аккаунты (требуют подключения Supabase)

См. [SUPABASE_SETUP.md](SUPABASE_SETUP.md). Без заполненного `config.js` приложение продолжает работать локально. Облачный режим хранит отдельный дашборд для каждого аккаунта, проверяет версию перед записью и позволяет перенести локальные задачи явно. Реальная изоляция пользователей должна быть проверена на настроенном проекте перед приглашением отдела.

## Проверки

При запущенном сервере и установленном Playwright + Chromium:

```sh
node tests/backup-export.cjs
node tests/accounts-journal.cjs
```

Другой адрес можно задать через `PORYADOK_TEST_URL`. Тесты используют отдельные браузерные профили, не меняют пользовательские данные. Cloud-тест моделирует API и проверяет поведение клиента при смене аккаунтов, конфликтах, потере сети и выходе во время загрузки. Он не заменяет проверку настоящего Supabase/RLS, описанную в SUPABASE_SETUP.md.

## Рабочее и личное

Переключатель сверху открывает два планировщика с независимыми задачами, категориями, поиском и счётчиками. Оба раздела принадлежат текущему пользователю; рабочий раздел не становится общим для отдела. В карточке можно изменить планировщик и категорию, сохранив ID и историю задачи.

Старые записи без поля `workspace` читаются совместимо: категория с ID `personal` и её задачи относятся к личному планировщику, остальные — к рабочему. Миграция сохраняет названия, ID, заметки и статусы и записывается при следующем сохранении. Облачная таблица и SQL менять не требуется — оба раздела входят в существующий JSON. Резервная копия включает оба раздела, CSV добавляет столбец «Раздел».

## Установка и быстрый запуск

На сайте нажмите «Установить»:
- Windows: установите приложение через Chrome/Edge или скачайте .url-ярлык выбранного раздела и перенесите его на рабочий стол.
- iPhone/iPad: Safari → Поделиться → На экран Домой. Включите открытие как веб-приложение, если переключатель доступен.
- Android: Chrome → меню → Установить приложение / Добавить на главный экран.

Это иконки и ярлыки, не системные виджеты со списком задач. Веб-приложение использует `manifest.webmanifest`, PNG-иконки и service worker только для статических файлов. Установка браузером зависит от версии и возможностей платформы. Быстрые действия «Рабочее»/«Личное» из манифеста поддерживаются не всеми ОС; обычный переключатель доступен везде.

После первого открытия статические файлы и локальные задачи доступны офлайн. Облачные запросы требуют сети, ответы Supabase и токены не кэшируются service worker. В отдельном приложении/профиле может потребоваться повторный вход. Местные задачи не переносятся автоматически в другое браузерное хранилище — используйте экспорт/импорт или перенос в аккаунт.

Дополнительная проверка (с работающим сервером): `node tests/workspaces-install.cjs`. Проверяет совместимость старых данных, оба раздела, перенос задачи, резервную копию, ярлыки, мобильный экран, манифест и настоящую работу service worker офлайн. Нативную установку на Windows/iOS/Android нужно проверить на устройствах. Для проверки пути GitHub Pages можно запустить сервер из `/workspace` и задать `PORYADOK_TEST_URL=http://127.0.0.1:8001/dashboard/`.

## Проверка доступа и бесплатные лимиты

В «Мой аккаунт» доступна проверка двух пустых тестовых пользователей на реальном Supabase: «Проверить разграничение доступа». Пароли вводятся только на сайте; тестовые задачи очищаются после проверки. См. [LIMITS_AND_SECURITY.md](LIMITS_AND_SECURITY.md) — условия тарифов, выполненные проверки и ограничения размещения на GitHub Pages. 13 октября 2026 года пользователь сообщил об успешном прохождении всех 9 проверок на реальном проекте. Подробности и пределы подтверждения описаны в указанном документе.

Для фонового обновления приложение сначала читает только номер версии. Полный дашборд загружается, если версия изменилась; данные и фильтры не сбрасываются при отсутствии обновлений.

## Портфель брендов

Рабочий экран теперь показывает карточки брендов и направлений. Выберите бренд, чтобы раскрыть его задачи; создайте новый через «Добавить бренд». У каждого бренда есть описание, цвет, активные/ожидающие/завершённые задачи и ближайший срок. Фильтр «Требуют внимания» объединяет высокий приоритет и просрочку. В карточках задач сохранены журнал, отчёты и подтверждение завершения; добавлено время срока.

Личный планировщик остаётся отдельным. Существующие категории и задачи сохраняются; менять схему Supabase не требуется. Наполнение из отчётов XLSX выполняется отдельной командой с предпросмотром; исходные файлы и рабочие записи не включаются в публичный код. Подробнее: [PORTFOLIO_DESIGN.md](PORTFOLIO_DESIGN.md).

Проверка нового сценария: `node tests/portfolio.cjs` (при запущенном сервере; адрес задаётся через `PORYADOK_TEST_URL`).

## Добавление из отчёта XLSX

Кнопка «Добавить из Excel» на главном экране или в меню данных читает файл локально в браузере. Поддерживается таблица с заголовками «Задача», «Статус», «Результат / что сделано», «Что осталось сделать», «Срок», «Причина задержки / помощь», «Комментарий». Бренд/направление и приоритет — необязательные дополнительные колонки. Без бренда предлагаются общие задачи, без приоритета — средний. Нельзя угадать поставщика только по упоминанию в названии: предложенную раскладку следует сначала записать в дополнительную колонку Excel или выбрать в предпросмотре.

До сохранения можно исправить бренд, статус, приоритет и срок, исключить строки. Результаты, следующие действия, задержки и комментарии сохраняются в журнале и в метаданных источника. Числовые даты Excel преобразуются в календарные даты; неоднозначные текстовые сроки не превращаются в придуманный дедлайн. Завершённые записи сохраняют статус. Даты журнала — время добавления, а не выдуманное время прошлых событий.

Добавление сохраняет существующие задачи, категории и заметки. Повторные строки того же отчёта распознаются по листу, периоду, номеру и названию; они не обновляют и не перезаписывают уже внесённые записи. Похожие названия не выбраны автоматически — их можно явно разрешить добавить отдельно. В локальном режиме данные сохраняются в браузере, после входа — в своём облачном дашборде с прежней проверкой версии.

Чтение XLSX не использует сторонний CDN и не выполняет макросы/формулы. Проверяются CRC ZIP-частей и размеры, запрещены сущности XML и внешние листы. Формулы читаются только при наличии сохранённого результата; неподдерживаемые статусы, повреждённые и слишком большие книги отклоняются до записи. Импорт предназначен для отчёта с заголовками, а не для произвольной книги с любым макетом. Размер файла и распаковки — до 20 МБ; до 30 листов, до 5000 строк на лист и до 5000 задач в одном добавлении. Требуется браузер с DecompressionStream deflate-raw; проверено в Chromium, установка на конкретном iOS/Android отдельно не проверялась.

Проверка: `node tests/report-import.cjs` с `PORYADOK_TEST_URL`, как у остальных браузерных тестов. Для генерации независимого тестового XLSX требуется Python openpyxl (в облачной среде уже установлен); приложение не требует Python или библиотек Excel в браузере. Тестовый файл синтетический, пользовательских отчётов в репозитории нет.

## Шаблон и отчёт за период

Меню «Данные» → «Скачать пустой XLSX» даёт пустую книгу с заголовками, выпадающими статусами/приоритетами и инструкцией. Заполняется лист «Задачи», затем загружается через «Добавить из Excel». Поле A2 задаёт период/название списка; для новых повторяющихся задач задайте новый период. Повторы прежнего списка пропускаются. Импорт по-прежнему добавляет рабочие задачи, а не синхронизирует изменения существующих записей.

«Отчёт за период» формирует настоящий XLSX с оформлением, фильтрами и закреплёнными заголовками: сводка, канонический список задач, журнал, события периода, известные завершения, переносы, текущие активные задачи и импорт периода. Период включителен и считается в часовом поясе браузера. Текущий статус — на дату формирования, не снимок на конец прошлого периода. Даты завершения не угадываются. Старые точные системные записи завершения учитываются; импорт исходных результатов выделяется отдельно от действий пользователя. Новые изменения статуса, срока, категории и раздела сохраняют тип события и значения до/после. Полный журнал вынесен построчно; слишком длинные сводные ячейки помечаются сокращёнными. Данные не отправляются на внешнюю службу формирования файлов.

В предпросмотре Excel появились фильтры (без срока, без бренда, в работе, завершённые, новые), сортировки и создание бренда в подсказках до окончательного добавления. Фильтр не меняет выбранные галочки: можно снять весь выбор, отфильтровать и выбрать показанные новые строки.

## Бренды и общие задачи

Обязательная категория inbox и категории с `kind: general` вынесены в «Без бренда / другие». В портфеле рабочих брендов их нет; задачи остаются в отдельном списке. Тип задаётся в настройках категории. Существующие категории автоматически не переклассифицируются, кроме обязательного inbox. ID и задачи сохраняются при смене типа. В шаблоне есть необязательный «Тип категории»: Бренд / Другие. Для личного раздела разделение по брендам не применяется.

Основной текст увеличен до 14–16 px, второстепенные подписи до 12 px, усилены цвета и статусы. Ориентиры: Microsoft Fluent typography (https://fluent2.microsoft.design/typography) и WCAG contrast minimum (https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Это применение правил, а не утверждение о полном аудите соответствия WCAG.

Проверка сквозного сценария: `node tests/excel-workflow.cjs` с работающим сервером. XLSX дополнительно проверяется независимым openpyxl: стили, листы, события периода и обратный импорт шаблона.

## Навигация и доска задач

Бренд открывается отдельным экраном вместо раскрытия под длинным портфелем. «К брендам» возвращает прежнюю прокрутку и фокус карточки. Переключение «Список / Доска» сохраняет выбранный бренд и фильтры; вид задач запоминается в браузере. Доска группирует задачи по четырём имеющимся статусам. На компьютере работает перетаскивание; на телефоне и с клавиатуры статус меняется через список в карточке. Завершение любым способом требует подтверждения и сохраняется в истории. На телефоне горизонтальная прокрутка ограничена доской.

В меню файлов три основных сценария: готовый отчёт XLSX, пустой шаблон XLSX и загрузка XLSX с предпросмотром. JSON остаётся резервной копией обоих планировщиков. Упрощённый CSV находится в закрытом разделе «Дополнительно» и явно описан как таблица для других программ.

Визуальные ориентиры изучены по публичным страницам [GanttPRO](https://ganttpro.com/ru/) и [Kanbano](https://kanbano.ru/): постоянная навигация, отдельная рабочая область, колонки статусов, контрастные карточки и компактные метки. Интерфейс и стили собственные, сторонние изображения и код не включаются.

`node tests/navigation-board.cjs` проверяет возврат к прежнему месту в большом портфеле, переносы между колонками, отмену/подтверждение завершения, историю, сохранение вида и мобильную прокрутку. Тесты используют синтетические локальные данные.
